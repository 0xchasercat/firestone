Restore a snapshot

Restoring is a whole-machine rollback of : its disk, its firestone.toml and its published VM config are all replaced from the snapshot. Anything written since it was taken is gone, and the machine comes back to the configuration its disk was captured under.

This is a warm snapshot, so the machine always starts again afterwards: a memory image only means something resumed.

Clone machine

Copies 's spec byte for byte, and by default its disk, into a machine that has never run. The base image is shared, never duplicated.

A copied disk carries the guest's own /etc/machine-id and hostname. An empty disk re-provisions from the base image and avoids that.

Delete cached image

This removes from this host's image store. A machine or a snapshot that pins it keeps it: Firestone refuses and names what is holding it.

Prune unused images

Removes every cached image no machine and no snapshot references. Anything still pinned is kept, so this cannot break a machine you can still start.
