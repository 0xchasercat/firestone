# virtiofsd distribution verification

This record covers the Firestone-owned virtiofsd v1.14.0 build recipe. The first pull request establishes reproducible candidate binaries. Publication and `deps.toml` binary pins follow only after review and merge.

The outer script accepts only HTTPS downloads and checks the source and native-library hashes before starting a container. Cargo uses the committed lockfile with `--locked`; Cargo verifies registry package checksums recorded in that file. The container runs without capabilities, with a read-only root filesystem, and can write only to its temporary build mount and the caller's explicit output directory.

## Build flags

The release build uses upstream's static-link requirements and fixes inputs that can affect generated bytes:

```text
cargo build --locked --release --target <target>
RUSTFLAGS=-C target-feature=+crt-static -C link-self-contained=yes -C debuginfo=0 -C codegen-units=1 -C metadata=firestone-virtiofsd-v1.14.0 -C link-arg=-Wl,--build-id=none --remap-path-prefix=/work=/firestone-build --remap-path-prefix=/usr/local/cargo=/rust-cargo --remap-path-prefix=/usr/local/rustup=/rust-toolchain
CARGO_INCREMENTAL=0
CARGO_PROFILE_RELEASE_CODEGEN_UNITS=1
CARGO_PROFILE_RELEASE_DEBUG=0
CARGO_PROFILE_RELEASE_LTO=true
LIBCAPNG_LINK_TYPE=static
LIBSECCOMP_LINK_TYPE=static
SOURCE_DATE_EPOCH=1783331602
TZ=UTC
```

The recipe runs the target strip tool after linking. It then checks the ELF machine, rejects `PT_INTERP` and dynamic `NEEDED` entries, requires mode 0755, and runs the x86_64 binary with `--version`.

## Reproduction commands

Run each target twice into four empty directories outside the worktree:

```sh
scripts/build-virtiofsd.sh --arch x86_64 --output-dir /tmp/virtiofsd-x86-run-1
scripts/build-virtiofsd.sh --arch x86_64 --output-dir /tmp/virtiofsd-x86-run-2
scripts/build-virtiofsd.sh --arch aarch64 --output-dir /tmp/virtiofsd-arm-run-1
scripts/build-virtiofsd.sh --arch aarch64 --output-dir /tmp/virtiofsd-arm-run-2
```

The GitHub workflow performs the same four clean builds, compares each target byte for byte, writes `SHA256SUMS`, and retains both candidate artifacts for 14 days. It never publishes a release.

## Publication boundary

The candidate binaries are not dependency pins. After the orchestrator reviews and merges this recipe, the orchestrator will publish both files as Firestone prerelease assets. A follow-up pull request will download those immutable URLs, verify their hashes, change `deps.toml` from `source-only` to `binary`, and update `scripts/pin-deps.sh`. Until that work lands, `doctor --fix` must continue to report the virtiofsd distribution gap.
